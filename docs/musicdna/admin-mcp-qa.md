## Privacy and roles

Pairing catalog inspection uses `catalog_read`; all `qa_*` and `models_*` tools require `qa_read`. Catalog access never implies interview access.

A session must additionally be owned by the caller, be an owner-QA session created by that caller, or have an explicit, unexpired, unrevoked session scope. **No scope grants are seeded.** Even an existing admin's role alone does not enumerate other listeners' sessions through these tools. Approval/scope management is not an MCP tool.

The new security-barrier views are intentionally owner-executed narrow projections over existing admin-only diagnostics, filtered on every row by a fresh capability + ownership/scope predicate. They change no base-table grants/RLS. The privileged predicate returns only a boolean; it cannot expose Auth records or accept an arbitrary actor. Views omit user IDs, emails, private chat/self-report, prompts, source credentials, provider error bodies, raw local-only diagnostic text, sharing tokens, learning payloads and leases. Unknown session and unauthorized session both yield not found. Hosted PostgREST/RLS acceptance remains required in addition to native fixtures.

## Prospective quip receipts

Only **Admin → New QA interview** opens the web interview with `qa=1`. The flag is just an eligibility-query hint; it grants nothing. The server requires the registered caller's QA role, ownership and existing owner-QA tag. Ordinary and guest interviews do not start this telemetry path. It does not imply synthetic eligibility, enrollment or learning consent.

On a displayed approved static waiting line, a non-blocking animation-frame observation records the line's hash, copy/pacing version, stable wait ID, sequence, choice position, phase, client display time, monotonic duration/delay and hidden/unmounted reason. No song title, response, free-text input or raw line prose is stored. Web server functions and the additive mobile endpoint use the same adapter/RPC:

- `GET /api/v1/session/:id/qa-quips`: `{allowed: boolean}`; normal authenticated caller, no harness key.
- `POST /api/v1/session/:id/qa-quips`: observation fields from `QuipObservation` minus `session_id`; a fresh UUID `id` is the idempotency key. Keep the exact payload/ID if retrying an uncertain acknowledgement.
- Body: `id`, `wait_id`, `line` (must exactly match approved static copy), `sequence`, `answered`, `phase` (`post_pick_wait` or `final_writing`), `shown_at` UTC, `duration_ms`, `since_wait_ms`, `ended_reason` (`changed_or_unmounted` or `document_hidden`).
- Signed out: 401; not owner-QA/permitted: 403; changed-ID payload conflict: 409; invalid input: 400; unavailable persistence: 503. `recorded:false` means unsupported copy, not a successful receipt.
- Direct authenticated table writes are denied; the RPC is owner-QA checked, append-only, audited, idempotent and capped at 1,000 observations per session under a session lock. No engine-driving event, score or learning table is changed.

These are **client-reported paint segments**, not independent video proof. Permission lookup can delay initial coverage; tab closure/backgrounding or network failure can lose segments. Split phase segments count once per wait/sequence/line in pacing metrics. Dynamic skip/preparation lines and older/mobile clients without this instrumentation remain unmeasured. A current approved line is returned only when its hash/version matches a stored display receipt; source-code timers/pools alone never become a historical display timeline. Future copy changes can leave old hashes unresolved, which is reported honestly.

Flutter has an additive observation contract but has not been instrumented or released by this PR. Normal interview pacing/buttons/picks and model calls are unchanged.
